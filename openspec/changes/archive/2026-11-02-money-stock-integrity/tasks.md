## Sequencing Issues Flagged (not silently resolved)

**Issue A — migration diff size is unpredictable and partly mechanical.** Deleting 8 migration dirs and regenerating one baseline (1.3–1.4) can swing the Phase 1 line count by hundreds of lines in either direction, dominated by auto-generated SQL rather than hand-written logic. Recommend reviewing 1.1–1.2 (money.js + schema.prisma) and 1.3–1.5 (migration regen) as two separate commits inside PR 1 so the generated-SQL noise doesn't bury the real logic change — flagging for the product owner rather than deciding the PR boundary myself.

**Issue B — Phase 1 and Phase 2 cannot deploy independently.** The design's own Rollout section states the Decimal schema and the `res.json` serializer are "a matched pair" that must deploy together: once `schema.prisma` goes live with Decimal columns, Prisma returns raw `Decimal` instances for every money field in every existing, unmodified endpoint — which serialize to JSON as strings — until the serializer (Phase 2) is also live. This means PR 1 and PR 2, while reviewable separately, MUST merge-and-deploy together (or PR 1 must not be deployed until PR 2 also merges) to avoid a broken intermediate state in production. This is not a hidden conflict the design missed, but it is easy to lose track of once PRs 1 and 2 are split for review — calling it out explicitly so `sdd-apply` does not deploy PR 1 alone.
